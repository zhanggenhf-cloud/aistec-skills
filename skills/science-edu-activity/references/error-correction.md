# 纠错机制 (Error Correction)

本文档定义了活动方案生成过程中的多层纠错机制，确保输出质量。

## 纠错层级架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 3: 输出后验证 (Post-Output Verification)            │
│  - 完整性检查 / 科学性检查 / 安全性检查                      │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 生成中监控 (Generation Monitoring)               │
│  - 格式约束 / 内容约束 / 实时校验                           │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: 输入预处理 (Input Preprocessing)                 │
│  - 输入解析 / 意图识别 / 需求澄清                           │
└─────────────────────────────────────────────────────────────┘
```

## Layer 1: 输入预处理

### 1.1 输入分类与路由

根据输入类型选择不同的解构策略：

| 输入类型 | 识别特征 | 处理策略 |
|---------|---------|---------|
| 科学概念 | 抽象术语、定律名称 | 概念→原理→应用路径 |
| 展品介绍 | 实物描述、功能说明 | 实物→原理→互动设计路径 |
| 活动需求 | 目标人群、时长要求 | 目标导向反向设计 |
| 混合输入 | 同时包含多种元素 | 多路径融合 |

### 1.2 需求澄清检查点

当输入信息不足时，触发澄清流程：

**必须澄清的情况：**
- [ ] 科学概念过于宽泛（如"物理"）
- [ ] 展品描述缺少核心功能说明
- [ ] 目标年龄段不明确
- [ ] 活动时长未指定
- [ ] 参与人数范围未知
- [ ] 可用资源/场地限制未说明

**澄清话术模板：**
> "为了设计更适合的活动方案，我需要确认几个问题：
> 1. ...
> 2. ...
> 3. ..."

### 1.3 输入预处理输出

生成标准化的内部表示：

```json
{
  "input_type": "concept|exhibit|requirement|mixed",
  "extracted_entities": {
    "topic": "主题",
    "discipline": "学科",
    "keywords": ["关键词"],
    "constraints": {
      "age_range": "年龄",
      "duration": "时长",
      "group_size": "人数",
      "resources": ["资源限制"]
    }
  },
  "confidence": 0.95,
  "clarification_needed": false,
  "processing_strategy": "策略名称"
}
```

## Layer 2: 生成中监控

### 2.1 知识解构约束

**结构约束检查：**
- [ ] 知识点是否形成完整树状结构
- [ ] 每个知识点是否有儿童友好的解释
- [ ] 知识点之间是否存在循环依赖
- [ ] 是否有孤立的知识点

**内容约束检查：**
- [ ] 科学概念解释是否准确
- [ ] 是否存在超纲内容
- [ ] 类比是否恰当（不会引起新误解）
- [ ] 示例是否贴近目标年龄段生活

### 2.2 活动设计约束

**流程完整性：**
- [ ] 是否包含引入→探索→讨论→应用四阶段（或所选框架的全部阶段）
- [ ] 各阶段时间分配是否合理
- [ ] 阶段间过渡是否自然
- [ ] 所选框架的阶段是否完整（如5E的5个阶段、PBL的5个阶段）

**框架选择检查：**
- [ ] 所选框架是否与主题特征匹配？（争议议题→SSI，工程设计→Design Thinking...）
- [ ] 框架选择理由是否充分说明？
- [ ] 如混合框架，各阶段衔接是否自然？

**UDL 覆盖检查：**
- [ ] 每个核心概念是否有 ≥2 种表征方式？
- [ ] 每个学习目标是否有 ≥2 种表达选项？
- [ ] 参与者是否有路径/难度/角色的选择机会？
- [ ] 是否有为视觉/听觉/阅读障碍者的替代方案？
- [ ] 时间压力是否可调节？
- [ ] 是否有为注意力易分散者的结构化支持？

**形成性评估检查：**
- [ ] 每个学习目标是否有至少一个检查点？
- [ ] 检查点是否嵌入活动流程（不在末尾一次性评估）？
- [ ] 检查方式是否多样（观察/提问/作品/讨论/自评）？
- [ ] 是否有明确的"成功指标"和"未达标应对策略"？

**STEM/STEAM 检查（如适用）：**
- [ ] 整合是否自然（不是硬凑）？
- [ ] 是否有明确的"整合问题"驱动？
- [ ] 各学科角色是否清晰？

**SSI 检查（如适用）：**
- [ ] 议题是否真实且当前存在争议？
- [ ] 是否提供了至少2种对立的科学证据？
- [ ] 是否识别了至少3种不同利益相关者的视角？
- [ ] 是否避免了预设"正确答案"？
- [ ] 是否有论证框架（主张→证据→推理→反驳）？

**可操作性：**
- [ ] 材料是否容易获取
- [ ] 操作步骤是否清晰可执行
- [ ] 是否有明确的成功标准
- [ ] 时间估算是否现实

**安全性：**
- [ ] 是否识别所有潜在风险
- [ ] 是否有足够的安全措施
- [ ] 是否有应急预案

**ICAP 认知参与层次：**
- [ ] 每个活动阶段是否标注了目标 ICAP 档位（P/A/C/I）？
- [ ] 整体 ICAP 趋势是否呈上升或稳定在高挡？
- [ ] 是否存在连续多个 P 档阶段？
- [ ] 升档策略是否具体可操作？

**元认知嵌入：**
- [ ] 活动前是否有预测/目标设定环节？
- [ ] 活动中是否有监控/自我提问节点？
- [ ] 活动后是否有反思/调整环节？
- [ ] 反思提示是否具体（不是泛泛的"反思一下"）？

**动机设计（SDT）：**
- [ ] 学习者是否有有意义的选择？
- [ ] 成功标准是否明确且可达？
- [ ] 是否有即时反馈机制？
- [ ] 每个人是否有不可替代的角色？
- [ ] 是否预留了"有效失败"的空间？

**明暗线对齐：**
- [ ] 每个"有趣"的活动环节能否指认其服务的教学目标？
- [ ] 是否存在"为了热闹而热闹"的环节？
- [ ] 活动流程的暗线（教学目标）是否清晰？

### 2.3 实时纠正触发器

当检测到以下问题时，立即触发纠正：

| 问题类型 | 检测信号 | 纠正动作 |
|---------|---------|---------|
| 概念错误 | 与已知科学知识冲突 | 重新检索权威来源 |
| 超龄内容 | 涉及目标年龄段未学的知识 | 降维解释或跳过 |
| 不可行操作 | 材料过于昂贵/危险/难获取 | 寻找替代方案 |
| 逻辑跳跃 | 知识点之间缺乏过渡 | 补充中间步骤 |
| 时间失衡 | 某阶段时间过长/短 | 重新分配 |

## Layer 3: 输出后验证

### 3.1 完整性检查清单

**必须包含的元素：**
- [ ] 方案名称
- [ ] 基本信息（年龄/时长/人数/学科）
- [ ] 学习目标（至少3个，覆盖不同层次）
- [ ] 背景知识（科学原理+现实应用+验证标注）
- [ ] 教学法框架（框架选择+理由+映射）
- [ ] UDL 差异化设计（多元表征+表达+参与）
- [ ] 活动流程（完整框架阶段+形成性评估检查点）
- [ ] 材料清单
- [ ] 安全提示
- [ ] 评估方式（形成性+总结性+参与度+UDL替代）
- [ ] 参考资料（真实文献引用）

**格式检查：**
- [ ] 使用标准 Markdown 格式
- [ ] 表格格式正确
- [ ] 层级标题正确（#/##/###）
- [ ] 列表标记一致

### 3.2 科学性验证

**概念准确性检查：**
1. 核心理论是否表述正确
2. 公式/定律引用是否准确
3. 单位使用是否规范
4. 因果关系是否成立

**常见科学错误模式：**
- ⚠️ 混淆相关与因果
- ⚠️ 过度简化导致本质错误
- ⚠️ 使用过时/被推翻的理论
- ⚠️ 忽略边界条件和适用范围

### 3.3 安全性检查

**高风险活动标识：**
| 风险类别 | 具体表现 | 必须措施 |
|---------|---------|---------|
| 化学风险 | 腐蚀性/有毒化学品 | 防护装备+急救措施 |
| 物理风险 | 高温/尖锐/高速 | 安全距离+操作规范 |
| 生物风险 | 活体/微生物 | 消毒+废弃物处理 |
| 环境风险 | 户外/水域 | 应急预案+监护要求 |

**安全检查流程：**
1. 识别活动中所有可能的风险点
2. 评估风险等级（高/中/低）
3. 为高风险点制定防护措施
4. 确认是否有替代方案降低风险
5. 验证应急措施的可行性

### 3.4 教育有效性检查

**布鲁姆分类覆盖：**
- [ ] 至少包含记忆/理解层次的目标
- [ ] 至少包含应用层次的目标
- [ ] 鼓励包含分析/评价/创造层次

**参与式设计：**
- [ ] 是否有动手环节
- [ ] 是否有讨论/互动环节
- [ ] 是否有选择和决策机会
- [ ] 是否允许不同水平参与者都获得成就感

## 自动纠错触发条件

以下情况将触发自动重新生成或修正：

```yaml
triggers:
  - condition: "缺少必要章节"
    action: "补全缺失部分"
    
  - condition: "科学概念明显错误"
    action: "重新解构知识"
    
  - condition: "安全提示缺失"
    action: "添加安全评估章节"
    
  - condition: "活动时长与阶段不匹配"
    action: "重新分配时间"
    
  - condition: "材料清单不完整"
    action: "补充材料和规格"
    
  - condition: "学习目标与活动不对应"
    action: "调整目标或活动设计"
```

## 人工审核标记

某些情况需要人工确认：

> ⚠️ **需要确认**：本活动涉及[具体内容]，请确认：
> 1. 目标年龄段是否适合接触此内容？
> 2. 场地和设备条件是否满足？
> 3. 是否需要专业人员陪同？

## 迭代改进记录

每次生成后记录：
- 输入类型和处理策略
- 触发的纠正次数和类型
- 用户反馈（如果有）
- 改进建议

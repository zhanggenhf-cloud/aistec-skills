## 三种工作模式

**模式识别**：根据用户请求判断意图

- **训练模式**：用户说"帮我练习…""我想提升…""训练一下…"
  - 给出练习任务 → 等待用户完成 → 提供反馈和改进建议
- **生成模式**：用户说"帮我写…""设计一个…""给我一份…"
  - 直接产出内容，参考对应模板和指南
- **评估模式**：用户说"评价一下…""看看这个怎么样…""帮我改改…"
  - 对照能力标准给出评分和改进建议

## 工作流程

### 步骤1：识别目标能力模块与内化需求
根据用户请求，匹配到五大能力模块之一。同时检查是否需要使用内化的高级功能：
- 用户需要**完整活动方案**（含知识解构、标准格式、科技馆适配）→ 使用 `activity-design.md` 中的完整内化流程
- 用户需要**展品深度研究**（含研究历史、文献验证、摘要翻译）→ 使用 `exhibit-knowledge.md` 中的内置验证流程
- 用户只需要**简化展品知识**（不涉及历史文献）→ 直接生成简化版知识包，跳过验证流程

若用户请求涉及多个模块，按优先级排序：展品知识 → 辅导词 → 实验 → 课程 → 短剧。

### 步骤2：加载对应资源
- 读取 `references/` 中对应模块的详细指南（含内化的高级能力）
- 读取 `assets/` 中对应模板（生成模式时使用）

### 步骤3：执行对应模式

**训练模式**：[训练流程] 见各参考文件中的「训练模式」章节
**生成模式**：[生成流程] 见各参考文件中的「生成模式」章节，使用对应模板
**评估模式**：[评估流程] 见各参考文件中的「评估标准」章节

### 步骤4：输出与反馈
所有输出必须包含：
- 明确的能力模块标签
- 工作模式标签
- 是否使用内化高级功能（如：含研究验证、含知识解构）
- 质量评分（1-5星）和具体改进点（评估/训练模式）
- 验证状态标注（如引用了研究脉络）
- 下一步建议

## 通用质量原则

所有能力模块共享以下原则：
1. **科学性优先**：内容准确，不编造原理、数据、历史事实
2. **受众导向**：根据目标受众（儿童/青少年/成人/家庭）调整深度和语言
3. **互动性**：鼓励提问、动手、讨论，避免单向灌输
4. **故事化**：用故事、情境、冲突引入科学概念，而非直接给定义
5. **安全边界**：涉及实验、表演时，明确安全注意事项

## 跨技能整合（已内化）

本 skill 已内化了以下技能的核心能力，无需外部调用：

### 内化的 `science-edu-activity` 能力（活动设计）
- **5-Stage 知识解构**：核心概念提取 → 知识点拆解 → 教学序列设计 → 活动形式匹配 → 难度分层
- **标准输出格式**：12 章节完整方案骨架（元数据、摘要、目标、背景、流程、材料、场地、人员、评估、应急、参考、附件）
- **多层纠错机制**：Layer 1 输入预处理 → Layer 2 生成中监控 → Layer 3 输出后验证
- **准确性保障**：Tier 1/2/3 来源分级、🔬📐🎭 标注规范、皮亚杰认知发展匹配
- **科技馆适配**：展厅寻宝、家庭互动、辅导员-观众模式、安全预案、备选方案

### 内化的 `research-lineage` 能力（展品研究验证）
- **五类幻觉检测**：TF（完全伪造）/ PAC（真实作者伪作）/ IH（信息不全）/ PH（拼接伪造）/ SH（微妙扭曲）
- **A→B→C→D 验证流程**：Semantic Scholar API → 书目细节交叉 → WebSearch 逐条验证 → 时间线一致性
- **摘要获取**：5 种途径（Semantic Scholar → arXiv → Crossref → WebSearch → Google Scholar）
- **文献翻译**：题目+摘要中文翻译，保留原文术语，不添加解读
- **溯源标注**：无标注/[待验证]/[信息来源有限]/[争议]/[推测]/[摘要未获取]

### 内化能力使用规则

- 当用户需要**完整教育活动方案**时，自动使用内化的 5-Stage 知识解构 + 标准输出格式 + 科技馆适配
- 当用户需要**展品深度知识包**（含研究历史）时，自动使用内化的验证流程 + 研究脉络梳理
- 当用户需要**展品知识但不涉及历史/文献**时，跳过验证流程，直接生成简化版知识包

## 跨模块组合提示（本 skill 内部）

用户可能请求组合能力：
- "帮我为一个电磁展品写辅导词，再设计一个配套实验" → 先加载 guide-script-writing.md，再加载 experiment-design.md
- "设计一个以航天为主题的科普活动，包含讲解、实验和表演" → 按活动设计框架整合三个模块

组合时以 activity-design.md 为总纲，嵌入其他模块的输出。
